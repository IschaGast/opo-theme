Opo Contrast Grid

Every color pair the build checks, drawn in its real colors. A theme only builds when every cell here passes, so this page is a picture of the gate, not a separate test.

Variant

Text on backgrounds

Rows are text colors, columns are the surfaces they are drawn on, including selection and diff tints composited the way editors draw them. Each cell shows the WCAG 2 contrast ratio and the level it reaches.

5 lowest ratios in this variant Below target (fails the build)

Inverted fills

Where a tool lets the theme set the text color, selections and search matches are a solid color with background-colored text. The fill must also stand out from the background as a UI state (3:1, WCAG 1.4.11).

In context

The same colors in an editor: syntax tokens, a selected line, added, removed and warning lines and a search match. Bold keywords and italic comments keep tokens apart without relying on color (WCAG 1.4.1).

Distinguishable under color vision deficiency

Pairs that carry meaning must stay apart for everyone. Each pair is simulated for normal vision and full-strength deuteranopia, protanopia and tritanopia; the smallest CIEDE2000 distance of the four has to reach the minimum. Pairs that also differ in bold or italic may sit closer.

Terminal colors

The 16 ANSI colors on the terminal background and on the selection tint. White on light and black on dark are surfaces by convention, so they are checked with the opposite text colors drawn on them, as in reverse video and status bars.

Generated by npm run build from src/palette.js. Ratios use the WCAG 2 relative luminance formula; color vision simulation uses the Brettel, Viénot and Mollon model at full severity (culori). Ratios are for normal vision; the simulation only changes how colors are shown.
